## Commands

- `npm run dev` — Next.js dev server.
- `npm run build` — Cleans `.next` cache (via `scripts/clean-next-cache.mjs`) then `next build`.
- `npm start` — Production server (port from `PORT`, prod uses `3001`).
- `npm run typecheck` — Runs `next typegen` then `tsc --noEmit`. Use this to verify types; there is no separate lint/test setup.
- `npm run db:generate` / `npm run db:push` / `npm run db:seed` — Prisma client gen, schema push, and `prisma/seed.ts` via tsx.
- `npm run admin:hash -- "password"` — Generates `ADMIN_PASSWORD_HASH` for the env file.

There is no test runner configured.

## Architecture

Next.js 16 App Router + React 19 + Prisma (PostgreSQL) + PayPal billing. TypeScript strict, path alias `@/*` → `src/*`.

### Host-based routing (critical)

The app serves two surfaces from one Next process, separated by HTTP host:

- `zenify.cx` (primary site host) — public marketing/landing pages under `app/` (pricing, features, solutions, signup, trial, etc.).
- `admin.zenify.cx` (admin host) — authenticated SaaS product (`app/app/*`) and admin tooling (`app/admin/*`).

`proxy.ts` (Next.js 16 replaces `middleware.ts` with `proxy.ts`; `export const config.matcher` still applies) enforces the split:

- On the primary host, requests to `/app/*` or `/admin/*` are redirected to the admin host.
- On the admin host, non-API requests outside `/app` and `/admin` are redirected to the admin home or login.
- `/admin/*` and `/app/*` UI require an admin session cookie; `/api/admin/*` returns 401 without one.
- Login/logout/redirect-after-login logic lives in `src/lib/admin-auth.ts` (session signing, host detection, `next` param normalization).

When changing route guards or hostnames, update both `proxy.ts` and `admin-auth.ts` together. `SITE_HOST` and `ADMIN_HOST` env vars drive host detection.

### Data model (`prisma/schema.prisma`)

The domain models a SaaS subscription lifecycle:

`Customer` → `Workspace` (status: TRIAL/ACTIVE/PAST_DUE/SUSPENDED/CANCELED) → one of `Trial` or `Subscription`, with `Invoice`, `PaymentAttempt`, `PlanChange`, `AccountLock` hanging off the workspace. `SignupLead` captures top-of-funnel before a `Customer` exists. `BillingWebhookEvent` is an idempotency log for PayPal webhooks (unique `eventId`).

Plans are an enum (`STARTER`/`GROWTH`/`BUSINESS`/`ENTERPRISE`); plan/seat changes are recorded as `PlanChange` rows rather than mutating `Subscription` directly.

### Billing (PayPal)

- Client-side checkout uses `@paypal/react-paypal-js` (`src/components/paypal-checkout.tsx`).
- Server endpoints under `app/api/paypal/{create-order,capture-order,webhook}` paired with `src/lib/paypal.ts` and `src/lib/billing.ts`.
- `app/api/cron/billing` is a scheduled endpoint protected by `CRON_SECRET` (see `src/lib/cron.ts`); it runs trial expiry, dunning, and invoice transitions.
- `PAYPAL_ENVIRONMENT` switches sandbox vs live; webhook verification uses `PAYPAL_WEBHOOK_ID`.

### Notifications and ops

- `src/lib/telegram.ts` posts ops/billing events to a Telegram chat (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`); admin endpoint at `app/api/admin/telegram`.
- `src/lib/db.ts` is the singleton Prisma client — import from here, never instantiate `PrismaClient` directly.
- `src/lib/site-data.ts` is the source of truth for marketing content (pricing tiers, features, etc.) consumed by landing pages.

### Admin auth

Session is a signed cookie (HMAC via `ADMIN_SESSION_SECRET`, TTL `ADMIN_SESSION_TTL_HOURS`). Single admin account: email `ADMIN_EMAIL`, bcrypt hash in `ADMIN_PASSWORD_HASH` (generated by `scripts/admin-password-hash.mjs`). There is no user signup for admin — provisioning is env-driven.

## Deployment

Push to `main` triggers `.github/workflows/deploy.yml`, which SSHes to the VPS (`14.225.7.175:1786`), pulls `/var/www/zenify`, runs `npm ci`, `next build`, and reloads pm2 (`ecosystem.config.js`, port 3001 behind nginx). First-time setup uses `scripts/bootstrap-server.sh`. Full env var list and one-time steps are in `DEPLOYMENT.md`.

## Conventions

- Server code lives in `src/lib/*` (shared) and `app/**/route.ts` (endpoints) / server components. Reusable UI components are in `src/components/`.
- Everywhere that needs the request host or session, go through `src/lib/admin-auth.ts` helpers (`isAdminHost`, `isPrimarySiteHost`, `getAdminSession`) — don't reparse `host` headers ad-hoc.
- The `/app` URL prefix is the authenticated product; `/admin` is internal ops. They share the admin-host gate but have separate layouts (`app/app/layout.tsx`, `app/admin/layout.tsx`).
